# `baton explain` and the `/baton` skill: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Task 1 creates matching items in baton's task store. Close each one there as its plan task lands (`node dist/baton.mjs task close <id>`), because the project's work items live in the task store, not in markdown lists.

**Goal:** `baton explain <thing> [--as <template>]` gathers the facts about one project element plus a voice template, and the new `/baton` skill lets an agent turn that into a short explanation. `/baton <anything>` mirrors the CLI.

**Architecture:** All logic lives in a new `src/core/explain/` module, made of pure functions plus small IO wrappers, unit-tested like the rest of `core/`. It has four parts: template store, name matcher, repo index of explainable targets, and fact collector. The command `src/commands/explain.ts` stays thin: it parses options, calls core and prints. The CLI never calls an AI model. The agent writes the explanation, guided by `plugin/skills/baton/SKILL.md`.

**Tech Stack:** TypeScript (ESM, Node ≥ 22.13), commander 15, yaml 2, vitest 5, Biome. No new dependencies.

**Spec:** [docs/superpowers/specs/2026-10-20-explain-design.md](../specs/2026-10-20-explain-design.md). Read it alongside this plan.

## Global Constraints

- `src/core/` never imports from `commands/`, `hooks/` or `mcp/`.
- Exit codes: 0 ok, 1 error, 2 blocked or refused (tie, `-c` on an existing name without `--force`, deleting a built-in), 3 not implemented. Throw `BatonError(msg, ExitCode.X)` from `src/core/errors.ts`, and let `action()` in `src/commands/_shared.ts` map it.
- `npm run check` (lint + typecheck + tests) passes at the end of every task.
- Skills use Agent Skills spec keys only. The `name` must equal the folder name (`npm run validate:skills`).
- No new runtime dependencies.
- Do not edit `.context/STATE.md`, `.context/tasks.jsonl` or `.context/memories.jsonl` by hand. Never edit an existing ADR. New ADRs are new hand-written files, as 0001–0009 were (spec: `baton decide` is a Phase 2 stub).
- Built-in templates: `caveman`, `baby`, `student`, `engineer`, `pitch`. Default `student`.
- Default length: under 150 words (`DEFAULT_MAX_WORDS = 150`).
- Template locations: project `.context/explain/<slug>.md`, personal `~/.baton/explain/<slug>.md`. Precedence: project, then personal, then built-in.
- `--scope` values: `both` (default), `project`, `personal`.
- Fact provenance labels: a `FreshnessLevel` for `.context/` facts, and the literal `no provenance` for everything else. Facts are labelled, never withheld.
- The exact output strings `closest match` and `no recorded reason` appear in text output. The skill depends on them.

## Review Focus

1. **Windows paths and line endings.** Docs with CRLF line endings parse the same as LF, and a query typed as `src\core\git.ts` resolves to the file `src/core/git.ts`. Pinned in Task 2 (matcher key normalization) and Task 4 (CRLF fixture).
2. **Scoped npm package names.** `baton explain @modelcontextprotocol/server` resolves to that exact dependency, even though `@` and `/` are not word characters. Pinned in Task 4.
3. **A bare repo.** A folder with no `package.json`, no `.context/`, no `docs/` and no git still answers (a file target) or reports "not found", and never crashes. Pinned in Task 6.
4. **Template name forms and copies that disagree.** `-c "Hackathon Judge"` is found by `--as "hackathon judge"` and `--as hackathon-judge`. When project and personal copies differ, the project copy is used. Pinned in Task 3.
5. **Output on a large repo is bounded.** A 40 KB doc section or a dependency imported by 50 files does not flood the agent. Fact text is capped at 1,200 characters, there are at most 20 facts, and at most 10 importers or source files are listed. Pinned in Task 5.

### Task 2: Name matching

**Files:**
- Create: `src/core/explain/match.ts`
- Test: `test/explain-match.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export function toKey(s: string): string;
  //   lowercase, NFKD, every run of non-letter/non-number → "-", trim "-". No length cap.
  //   "src\\core\\git.ts" and "src/core/git.ts" → "src-core-git-ts"; "@modelcontextprotocol/server" → "modelcontextprotocol-server"
  export function editDistance(a: string, b: string): number; // Levenshtein
  export interface Matchable { kind: string; name: string; keys: string[] } // keys already toKey'd
  export type MatchResult<T extends Matchable> =
    | { status: "exact"; matches: T[] }
    | { status: "closest"; matches: T[] }
    | { status: "tie"; candidates: T[] }
    | { status: "none"; suggestions: T[] };   // ≤ 3, nearest first, distinct names
  export function matchTargets<T extends Matchable>(query: string, targets: readonly T[]): MatchResult<T>;
  ```

**Algorithm (pinned, because the tests depend on it):**
1. `q = toKey(query)`. `exact` = targets with `keys.includes(q)`.
2. **Exact, several kinds.** If `exact` is non-empty, it's `exact`. Merge every kind. The one exception: if more than one `file`-kind target is in `exact` and they have different `name`s, the result is `tie` over those file targets (two `index.ts` files are different things).
3. **Otherwise, nearest.** Each target's distance is `min(editDistance(q, key))` over its keys. The threshold is `min(3, max(1, floor(q.length / 3)))`. `best` = the targets at the minimum distance, if that distance is ≤ the threshold.
4. **Closest or tie.** If `best` is non-empty: group it by `toKey(name)`. One group means `closest` with all of `best` (for example a section and a heading both named `hooks`). More than one group means `tie`.
5. **Otherwise, none.** The result is `none`, with the 3 nearest distinct names.

- [ ] **Step 1: Write the failing tests.**
  - `toKey normalizes separators and case`: the two path examples above, plus `toKey("Hackathon Judge") === "hackathon-judge"`.
  - `editDistance`: `("supabse","supabase") === 1`, `("","abc") === 3`.
  - `exact merges kinds`: a section `hooks` and a heading `Hooks` give status `exact` with 2 matches.
  - `two files with one basename tie`: two file targets keyed `index-ts`, named `src/a/index.ts` and `src/b/index.ts`. Query `index.ts` gives `tie` with 2 candidates.
  - `closest within threshold`: query `supabse` against dep `supabase` gives `closest`.
  - `fuzzy tie`: targets `cat` and `cot`, query `cut`, gives `tie`.
  - `none with suggestions`: query `zzzzzz` against 5 targets gives `none` with ≤ 3 suggestions.
  - `backslash path query matches`: a file target with keys `[toKey("src/core/git.ts"), "git-ts"]` and query `src\core\git.ts` gives `exact`.

- [ ] **Step 3: Implement** per the Interfaces block and the algorithm above.

**Interfaces:**

- Produces:
  ```ts
  export type TargetKind = "dependency" | "section" | "heading" | "file" | "mermaid";
  interface Base { kind: TargetKind; name: string; keys: string[]; source: string; line: number } // source = repo path
  export type Target =
    | (Base & { kind: "dependency"; version: string; dev: boolean })
    | (Base & { kind: "section"; section: Section })                       // .context/ section or whole-file doc
    | (Base & { kind: "heading"; level: number; body: string })            // docs/**/*.md
    | (Base & { kind: "file"; isDir: boolean })
    | (Base & { kind: "mermaid"; nodeId: string; edgesOut: string[]; edgesIn: string[] }); // edge entries are neighbour labels
  export interface Decision { section: Section; specSections: string[] }
  export interface RepoIndex {
    root: string;
    files: string[];            // repo paths, POSIX, no dirs
    contextSections: Section[]; // spec.md + rules.md sections, knowledge/*.md (NOT STATE.md, NOT decisions)
    decisions: Decision[];      // .context/decisions/*.md with an id
    targets: Target[];
  }
  export async function buildIndex(root: string): Promise<RepoIndex>;
  ```

**Rules:**
- **File list.** In a git repo: `git ls-files --cached --others --exclude-standard`. Otherwise walk the folder recursively, skipping `.git`, `node_modules`, `dist` and `.context/.cache`.
- **Directory targets.** Every parent directory of a listed file becomes a target, with `isDir: true`.
- **File and directory keys.** `toKey(path)` and `toKey(basename)`.
- **Dependencies.** Read `dependencies` and `devDependencies` from `package.json` at the root, if present. Keys: `toKey(name)`. The line is the line in `package.json` that holds the key.
- **Sections.** Sections are `contextSections` plus decisions. Keys: `toKey(id)` and `toKey(title)`. A missing `.context/` gives zero sections.
- **Headings.** Every `#`–`######` heading in `docs/**/*.md`. The body runs to the next heading of the same or higher level. Keys: `toKey(title)`. Line endings are normalized, so CRLF must not leak `\r` into names.
- **Mermaid.**
  - Scope: every ```` ```mermaid ```` fence in `docs/**/*.md`, `README.md` and `.context/**/*.md`.
  - What to read: node declarations `ID[Label]`, `ID(Label)`, `ID{Label}`, `ID((Label))` and `ID>Label]`, with or without quotes. Edges are the arrows `-->`, `---`, `-.->` and `==>`, with an optional `|text|`.
  - What to ignore: the `graph` or `flowchart` header, `subgraph`/`end`, `classDef` and `%%` comments.
  - Defaults: a node referenced with no label uses its id as the label.
  - Keys: `toKey(label)` and `toKey(id)`.
- **Malformed `.context/` content.** If a parser throws (duplicate id, bad marker), skip that file and keep going. `explain` must not die on a broken `.context/`.

### Task 5: Fact collection and the "no recorded reason" rule

**Files:**
- Create: `src/core/explain/facts.ts`
- Test: `test/explain-facts.test.ts`

**Interfaces:**
- Consumes: `Target`, `RepoIndex` and `Decision` (Task 4); `classifyFreshness` (`src/core/freshness.ts`); `commitsTouching` (`src/core/git.ts`); `matchesAny` (`src/core/glob.ts`); `Config` (`src/core/config.ts`).
- Produces:
  ```ts
  export type Provenance = FreshnessLevel | "no provenance";
  export type FactLabel = "package" | "import" | "section" | "decision" | "doc" | "layout" | "source" | "diagram";
  export interface Fact { label: FactLabel; source: string; text: string; provenance: Provenance } // source = "path:line"
  export interface FactBundle { facts: Fact[]; noRecordedReason: boolean }
  export const FACT_TEXT_MAX = 1200, MAX_FACTS = 20, MAX_LISTED = 10;
  export async function collectFacts(index: RepoIndex, targets: Target[], config: Config): Promise<FactBundle>;
  ```

**Rules:**
- **Provenance.**
  - `section` and `decision` facts: `classifyFreshness({meta, commitsSince}, config.freshness.staleAfter).level`. `commitsSince` is `commitsTouching(root, verifiedAt, sourcePaths)` when `verifiedAt` is set; if that call throws, use 0.
  - All other facts: `"no provenance"`.
- **"Mentions".** Text mentions a target when it contains the target's `name` as a case-insensitive whole token. Token boundaries are the start or end of the text, whitespace, or any of `` ` "'()[],.:; ``. For file targets, a file also counts as mentioned when its path matches a section's `sourcePaths` via `matchesAny`. A directory counts when any file under it does.
- **Facts per kind:**
  - **dependency:**
    - `package`: the `package.json` line.
    - `import`: one fact per importing file, up to `MAX_LISTED`. A file imports the dependency when it has extension `.ts`, `.tsx`, `.js`, `.mjs`, `.cjs` or `.jsx` and a line matches `from "<name>`, `require("<name>` or `import("<name>`, with an optional `/subpath`, using either quote type. The fact text is that line.
    - `decision` and `section`: every decision or context section that mentions it.
  - **section:**
    - `section`: its own body.
    - `decision`: every decision whose `specSections` include its id.
    - `source`: one fact listing up to `MAX_LISTED` files matching its `sourcePaths`.
  - **heading:**
    - `doc`: its body.
    - `decision` and `section`: every one that mentions the heading title.
  - **file:**
    - `layout`: lines in non-mermaid fenced blocks in `docs/**/*.md` whose first non-space token equals the basename, or the basename + `/`.
    - `decision` and `section`: every one that mentions it.
  - **mermaid:**
    - `diagram`: text is `"<label>: in ← <edgesIn>; out → <edgesOut>"`.
    - `doc`: the body of the heading enclosing the fence.
    - `decision` and `section`: every one that mentions the label.
- **Deduplication.** If several targets are merged, dedupe facts by `source` + `label`.
- **Caps.** Truncate `text` to `FACT_TEXT_MAX` with a trailing `…`. Keep at most `MAX_FACTS` facts, in this order: `section`, `decision`, `doc`, `package`, `diagram`, `layout`, `source`, `import`.

**Command shape (from the spec):**
```
explain [thing...]   (variadic; words joined with a space)
  --as <template>
  --format <text|json>      default text
  -c, --create <name>
  -p, --prompt <text>
  -s, --scope <both|project|personal>   default both

  --delete <name>
  --templates
```
- **Modes.** Exactly one of: `--templates`, `--create`, `--delete`, or a `thing`. None or several gives `BatonError` exit 1: `use one of: explain <thing>, --create, --delete, --templates`.

- **Explain mode.**

  - `tie` sets `process.exitCode = 2`, and `none` sets 1. Print to stdout in both cases so the skill can read it.
- **`--templates`.** One line per template: `<name>  <source>  <description>`.
- **Create and delete.** Print one line per written or removed path, e.g. `created .context/explain/hackathon-judge.md`. Show paths relative to the root, or with `~` for the personal dir.
