**Goal:** Build the Phase 1 deliverables from the roadmap's "Done when" column:

**Architecture:** All logic lives in `src/core/`, as pure functions plus small IO wrappers. Commands stay thin: parse, call core, print. Hooks call the same core through dynamic `import()`, behind a fast path in `src/cli.ts` that skips building the commander program. Data flows like this:

- `transcript.ts` → `handoff.ts` (recent tool calls) and `stats.ts` (metrics).
- `templates.generated.ts` → `init.ts`.

## Global Constraints

- **Layering.** `src/core/` never imports from `commands/`, `hooks/` or `mcp/`. Commands stay thin. Do not touch `src/program.ts`: every Phase 1 command is already registered there.
- **Exit codes.** 0 ok, 1 error, 2 check failed or blocked, 3 not implemented. Throw `new BatonError(message, ExitCode.X)` from `src/core/errors.ts`. `action()` in `src/commands/_shared.ts` maps it to stderr plus `process.exitCode`. Hooks always exit 0 unless a structured deny applies (ADR 0008).
- **Checks.**
  - `npm run check` (Biome, `tsc --noEmit`, vitest) passes at the end of every task.
  - Any task that changes `src/` ends with `npm run build`, so `dist/` and `plugin/dist/` stay in sync.
  - Skill tasks also run `npm run validate:skills`.
- **TypeScript.** `strict`, `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` are on. Set optional properties only when you have a value; never assign `undefined`. ESM imports use `.js` suffixes.
- **No new runtime dependencies.** Reuse the existing core functions each task names.
- **Hand-edit rules.**
  - Never hand-edit `.context/tasks.jsonl`, `.context/memories.jsonl` or `.context/STATE.md`. Use `baton task …`, `baton remember …` and `baton handoff`.
  - Never edit an existing ADR (0001–0011). New ADRs are new hand-written files copying the shape of `0008`, numbered from **0012**. `baton decide` is still a Phase 2 stub.
- **Explain files.** The explain side track (`bt-8ao`) is complete before this plan starts. Its files are not part of Phase 1, so leave them alone except in Task 20: `src/core/explain/**`, `src/commands/explain.ts`, `plugin/skills/baton/**`, `test/explain-*.test.ts`, `test/helpers/explain-fixture.ts` and `.context/explain/**`.
- **Windows.**
  - Every file read that is parsed first strips one leading UTF-8 BOM, then normalises CRLF/CR to LF: `text.replace(/^﻿/, "").replace(/\r\n?/g, "\n")`.
  - Repo paths are POSIX: replace `\` with `/`, or use `toRepoPath` from `src/core/paths.ts`.
  - Comparisons of absolute paths taken from transcripts are case-insensitive on `win32` only (pass the platform in, so tests can pin it).
- **Writes under `.context/`.** Use `writeFileAtomic(path, text)` from `src/core/tasks/native/jsonl.ts` (synchronous, temp file + rename). Write LF line endings. Two exceptions:
  - `verify-doc` keeps the file's existing line endings and BOM;
  - the drift log `.context/.cache/drift.jsonl` is append-only, written with `appendFile`, one JSON line per event.
- **Stamps.** `verified_at` is the first **12** hex characters of HEAD, always written double-quoted (`verified_at: "0123456789ab"`). Unquoted, an all-digit or `1e5…` SHA parses as a YAML number.
- **Packet header.** The packet's first line is exactly `# baton mission brief`, exported as `PACKET_HEADER` from `src/core/budget.ts`. `stats` relies on it.
- **Performance budgets.**
  - The real budgets are enforced by `scripts/hook-smoke.mjs` (Task 18), using the built CLI and median wall time:
    - `session-start`, `pre-compact`, `session-end`, and `mission` and `handoff --dry-run` on this repo: < 1000 ms;
    - `pre-tool-use` and `post-tool-use`: < 150 ms.
  - vitest timing checks are deliberately loose (< 3000 ms), so parallel forks on Windows do not make them flaky.
  - Hook handlers load core modules with dynamic `import()`.
  - Independent git calls run concurrently (`Promise.all`).
  - `git status` and `git diff` run with `--no-optional-locks`, so a hook never takes the index lock away from a live session.
- **Tests.**
  - Temp dirs come only from `makeTempDir()` or `makeRepo()` in `test/helpers/repo.ts` (Task 3). That module sets `process.env.GIT_CEILING_DIRECTORIES = tmpdir()` when it loads, so git never finds an ancestor repo: this machine's home folder is a git repo.
  - `findProjectRoot` walks up with `existsSync` and ignores that ceiling. A test that needs "no project here" must `git init` its temp dir, or give it a `.context/`.
  - Fixture git commands use `-c core.autocrlf=false`, and commits use `-c user.name=t -c user.email=t@t`.
  - Tests that read transcripts set `process.env.CLAUDE_CONFIG_DIR` to an empty temp dir. Tests that touch tasks set `process.env.BATON_ACTOR = "tester"`.
  - Tests never write this repo's `.context/` files. Dogfood tests only read them; reading through the task store may refresh the git-ignored `.context/.cache/tasks.db`, and that is fine.
  - Tests that `process.chdir` restore the cwd in `finally`. vitest's default `forks` pool allows `chdir`.
- **Commits.** End each task with a path-scoped commit: `git add <paths>`, then `git commit -m "<message>" -- <paths>`, with the same paths both times, always including `.context/tasks.jsonl`. Never `git add -A` or a bare `git commit`.
- **Task ids.** This plan assumes the ids in the Task-store map. If Task 1 recorded different printed ids (in a comment on `bt-s9g`), use those.

## Review Focus

1. **Windows paths, line endings and BOMs.**
   - Task 3: a CRLF or BOM-prefixed `.context/` parses to the same ids and lines as LF, and no `\r` or BOM leaks into bodies.
   - Task 7: `verify-doc` keeps a CRLF file CRLF, and keeps a BOM.
   - Task 11: transcript paths with backslashes and either drive-letter case resolve to repo paths on `win32`. A project has one transcript folder, whose name can differ in case from the encoded cwd (`n--…` for an `N:` cwd), so the folder is matched case-insensitively on `win32` only.
   - Task 17: hook stdin with a UTF-8 BOM, which PowerShell 5.1 adds, still parses.
   - Tests: temp dirs never see the ancestor git repo in this machine's home folder (`GIT_CEILING_DIRECTORIES`, Task 3).
2. **No self-ageing.** Commits that only change `.context/**` never count toward freshness: task-store writes, handoffs and the stamping commit itself (Task 5). Without this rule, `rules-continuity` (`source_paths: [".context/**"]`) goes stale after five task closes.
3. **The YAML number trap.** Stamps are quoted. Task 7 round-trips `"012345678901"` and `"1234e5678901"` as strings.
4. **Budget arithmetic.** The packet's `text.length ≤ maxChars` includes the header, the `\n\n` separators and the "Left out for space" line. Blocks are never cut (Task 9 has a tight-budget test).
5. **Nothing withheld leaks.**
   - Stale, unverified and superseded section bodies never appear in the packet, but their ids do (Task 9; dogfood in Task 10).
   - A nested marked section is its own section, and its text is not part of its parent's body (Task 3), so a withheld child cannot leak through a fresh parent.
6. **Idempotent handoff.**
   - STATE.md is excluded from its own `git status` and `diff --stat`.
   - A second run with no changes rewrites nothing: only `generated_at` and the "Last handoff" timestamp are ignored when comparing (Task 12).
7. **Secrets.** STATE.md is committed. Every tool-call summary is redacted and cut to 80 characters of argument, and absolute paths outside the repo are shortened to `…/<file name>` (Task 11).
8. **Fail open.** Invalid config, a broken `.context/` or a crashing handler gives stdout `""`, a `baton hook <event>:` line on stderr and exit 0. A broken spec file degrades the packet instead of removing it (Task 17).
9. **Dead-reference false positives.**
   - Git-ignored build output (`plugin/dist/`, `.context/.cache/…`) is not dead.
   - An inline-code path counts only when its first segment exists at the repo root (Task 5).
   - Shallow clones make old stamps read as stale. This is documented in ADR 0013, not worked around.
10. **Pre-tool-use stays under 150 ms.** The full bundle costs about 90 ms over bare node on Windows (implementation notes, Task 1). The `src/cli.ts` fast path and lazy handler imports (Task 17) are what keep the budget. Task 18 measures it.
11. **One freshness rule everywhere.** `drift`, `mission` and `explain` label a section's freshness through the same `evaluateFreshness` (Tasks 5 and 20). Explain keeps its `skipped` contract: index problems become one-line `skipped` entries.

- [ ] **Step 2: Write ADR 0012**, "Section index over .context/ and verify-doc stamps".
  - `source_paths: [src/core/sections.ts, src/core/verify-doc.ts, src/commands/drift.ts]`
  - `spec_sections: [context-format, freshness]`
  - **Context:** `drift`, `verify-doc`, `mission` and `explain` all need every section with its provenance. Ids must be unique across files (roadmap Phase 1), because tasks (`spec:<id>`) and `verify-doc` address sections by id. `parseSections` only rejects duplicates within one file.
  - **Decision Outcome bullets:**
    - **Scope and order.** `loadSectionIndex(root)` in `src/core/sections.ts` reads exactly these files, in this order: `.context/rules.md` and `.context/spec.md` (inline markers, ADR 0003), then `.context/STATE.md`, `.context/knowledge/*.md` and `.context/decisions/NNNN-*.md` (frontmatter). Nothing else under `.context/` is a section: not config, the task store, explain templates or the cache.
    - **Skipped silently.** Whole-file docs without an `id` (such as `knowledge/README.md`), and `decisions/0000-template.md` (number 0000 is the template).
    - **Normalisation.** Before parsing, a leading UTF-8 BOM is stripped and CRLF is normalised to LF. `file` is the repo-relative POSIX path.
    - **Nested sections.** A marked heading inside another marked section is a section of its own.
      - The outer section stays open until the next heading of the same or higher level.
      - Each line belongs to the innermost open marked section, so the outer body never contains a nested section's text. A withheld child therefore cannot leak through a fresh parent.
      - This fixes `parseSections`, which used to drop the outer section.
    - **One-line problems.** A problem message is one line that names its file.
    - **Unique ids.** Ids are unique across all files.
      - Strict mode (`drift`, `verify-doc`) fails with exit 1 and lists every problem.
      - Lenient mode (`mission`, `explain`) skips a broken file or a later duplicate, and records it as a problem.
    - **Decision fields.** For decisions the index also keeps the MADR `status`, `spec_sections` and `supersedes`. A status of `superseded by ADR-NNNN` sets `supersededBy: adr-NNNN`, because MADR has no supersedes field (ADR 0001).
    - **The stamp.** `verify-doc <ids...>` writes `verified_at: "<first 12 hex chars of HEAD>"`. It is double-quoted, because an all-digit or `1e5…`-shaped SHA would otherwise parse as a YAML number.
      - It rewrites only the `verified_at` token of the marker line or the frontmatter, and keeps the file's line endings and BOM.
      - It is all-or-nothing: an unknown id means nothing is written.
    - **ADR stamps.** Stamping an ADR's frontmatter is a metadata write through the CLI, allowed by ADR 0001's extension keys. The record's text never changes.
  - **Consequences.** Good: one parser and one id namespace for every consumer. Bad: a 12-character prefix could in theory become ambiguous in a very large repo, and widening it later is a format change that needs a new ADR.
- [ ] **Step 3: Write ADR 0013**, "Freshness from git history and dead references".
  - `source_paths: [src/core/drift.ts, src/core/git.ts, src/commands/drift.ts]`
  - `spec_sections: [freshness]`
  - **Context:** `classifyFreshness` (`src/core/freshness.ts`) is pure, and needs commit counts and dead references as input. One `git rev-list` per section is too slow for a session start under 1 s on Windows, where each git process costs about 50 ms (implementation notes §1). Naive counting also ages sections on every task-store commit.
  - **Decision Outcome bullets:**
    - **Counting.** Run one `git log --no-merges --no-renames --name-only` per distinct `verified_at` SHA. A section's count is the number of commits in `<sha>..HEAD` that change at least one file matching its `source_paths`, using baton's glob matcher. Merge commits are not counted.
    - **`.context/` is excluded.** Changes to files under `.context/` never count. Otherwise task-store writes, handoffs and the stamping commit itself would age `rules-continuity`-style sections on every commit. Edits to a section's own text are reviewed through `verify-doc` instead.
    - **Unknown SHAs.** A `verified_at` that is not a known commit (rebased away, or outside a shallow clone) is a dead reference, so the section is stale. CI that wants `drift --fail-on` needs a full clone.
    - **What counts as a dead reference.** Skipped when the project is not a git repo.
      - A `source_paths` glob that matches no existing file in `git ls-files --cached --others --exclude-standard`. Files deleted from the work tree do not count as existing.
      - A repo path in the section body: an inline-code span, or a relative markdown link, outside fenced code blocks. It is dead when its first path segment exists at the repo root but the full path neither exists on disk nor is git-ignored.
      - Body references in the generated `STATE.md` are not checked. STATE is regenerated, never edited, so a backticked path in it must not make it stale and drop the state head from the packet.

    - **The drift log** (`.context/.cache/drift.jsonl`, local and never committed).
      - Each `drift` run appends one line per aging or stale section: `{"v":1,"ts":…,"event":"flag","head":…,"id":…,"level":…,"commitsSince":…,"reason":…,"bodyHash":…}`.
      - `verify-doc` appends `{"v":1,"ts":…,"event":"verified","head":…,"id":…,"bodyHash":…}`.
      - `bodyHash` is the first 12 hex chars of the sha256 of the section body.
      - A flag followed later by a `verified` event with a different `bodyHash` means a human fixed the text, which confirms the flag. Phase 2 `stats` can compute precision from that.
  - **Consequences.** Good: freshness costs one git process per distinct SHA rather than per section, and stamping never ages anything. Bad: a section whose `source_paths` point into `.context/` never ages by commits, and dead-reference detection is a heuristic that misses plain-text paths.

**Rules (pinned, because the tests depend on them):**
1. **No `.context/`.** If `<root>/.context` does not exist, return `{ root, sections: [], byId: new Map(), problems: [] }`. Never throw.
2. **File order.**
   - `rules.md`, then `spec.md`: multi-section files, parsed with `parseSections`; `doc` is `rules` or `spec`.
   - `STATE.md`: `parseFileSection`; `doc` is `state`.
   - `knowledge/*.md`: top level only, sorted by file name with plain `<`; `doc` is `knowledge`.
   - `decisions/*.md`: names matching `ADR_FILE_RE` with a number ≥ 1, sorted by number; `doc` is `decision`.
   - Missing files and folders are skipped. `0000-*.md` is skipped **by name, before reading**: the template's id `adr-NNNN` is not kebab-case.
3. **Parsing.**
   - Read each file as UTF-8, strip one leading BOM, and normalise `\r\n?` to `\n`: `text.replace(/^﻿/, "").replace(/\r\n?/g, "\n")`. A BOM before `---` would otherwise defeat the frontmatter regex and silently drop the file.
   - Pass `.context/<relative path>` (POSIX) as the `file` argument.
   - If the parser throws, push a problem and skip the whole file. The message is the first line of `err.message`, trimmed. If it does not already start with the file path, prefix `${file}: `. Problems are always one line; YAML errors carry multi-line code frames.
   - If a whole-file doc has no `id` (`null`), skip it silently.
4. **Decisions.**
   - Take `data` from `parseFrontmatter`.
   - `status`: `typeof data.status === "string" ? data.status : ""`.
   - `specSections`: `Array.isArray(data.spec_sections) ? data.spec_sections.filter(isString) : []`.
   - `supersedes`: `data.supersedes == null ? omitted : String(data.supersedes)`.
   - If `meta.supersededBy` is unset and `supersededByFromStatus(status)` returns an id, set it. That function matches `/^superseded by\s+(?:adr[-\s]?)?(\d{1,4})\b/i` and returns `adr-` + the number padded to 4 digits.
5. **Cross-file duplicates.** Walk the sections in order. When an id is already in `byId`, push `{ file: s.file, message: \`${s.file}:${s.line}: duplicate section id "${id}" (also in ${first.file}:${first.line})\` }` and drop the later occurrence.
6. **Strict mode** (the default). If there are problems, throw `new BatonError(\`.context/ has ${n} problem(s):\n\` + problems.map((p) => \`  ${p.message}\`).join("\n"), ExitCode.Error)`.
7. **Nested marked sections (`parseSections` fix).** Today a marked `### Passkeys` under a marked `## Authentication` overwrites the open section, and `auth` disappears from the result. Rewrite the loop around a stack of open sections:
   - **On a heading of level L:** close every open section of level ≥ L. A closed section's body is its own collected lines, joined with `\n` and trimmed.
   - **If the next line is a baton marker:** parse it, push a new open section of level L, and consume the marker line (it is not body).
   - **An unmarked heading** is ordinary text: append it to the innermost open section, if there is one.
   - **Any other line** is appended to the innermost open section, if any.

**Rules (pinned):**
- **`stampMarkerLine`.** Find the `{…}` mapping inside `<!-- baton: … -->`.
  - If `/\bverified_at\s*:/` occurs, replace its value with `/(\bverified_at\s*:\s*)("[^"]*"|'[^']*'|[^,}]*?)(\s*[,}])/` → `` `$1"${sha}"$3` ``.
  - Otherwise insert `` `, verified_at: "${sha}"` `` before the mapping's last `}`.
  - Leave everything else on the line unchanged.
- **`stampFrontmatter`.** The text must start with `---\n`, otherwise throw. Inside the frontmatter block:
  - replace `/^verified_at:.*$/m` with `` `verified_at: "${sha}"` ``;
  - if there is no such line, insert it after the `kind:` line, or before the closing `---` when there is no `kind:` line either.
- **`stampSections`.**
  1. Load the strict index and dedupe `ids`. If any are unknown, throw `BatonError(\`no section(s): ${unknown.join(", ")}\`)` (exit 1) and write nothing.
  2. Group the ids by file. For each file:
     - read the raw text;
     - `bom = raw.startsWith("﻿") ? "﻿" : ""`, and `rest = raw.slice(bom.length)`;
     - `eol = rest.includes("\r\n") ? "\r\n" : "\n"`, and `lines = rest.split(/\r?\n/)`;
     - for `doc` `rules` or `spec`, set `lines[section.line] = stampMarkerLine(lines[section.line], sha)`. The marker sits on the line after the 1-based heading line;
     - for whole-file docs, run `stampFrontmatter(lines.join("\n"), sha)` and split again;
     - write `bom + lines.join(eol)` with `writeFileAtomic`, so the BOM and line endings survive.
  3. Reload the index. If any stamped id's `meta.verifiedAt !== sha`, throw `Error(\`verify-doc: stamp did not round-trip for ${id}\`)`.
  4. Return one `Stamp` per id: `previous` is the old `verifiedAt`.
- **`uncommittedSources`.** Map each porcelain line through `porcelainPath`, and return the paths that match `sourcePaths`, in input order.
- **Command `verify-doc <section-ids...>`:**
  1. `root = findProjectRoot()`, then `requireContext(root)`.

**Rules (pinned):**

- **Timestamps.** `startedAt` and `endedAt` are the lexical min and max of the record `timestamp` strings.

  - Normalise `root` and each `Read` tool use's `input.file_path` by replacing `\` with `/`, and lowercase both when `platform === "win32"` (default `process.platform`).

- **Tasks closed.**
  - Look at Bash tool uses that did not fail. Match the command against `/\btask\s+close\s+([^\n;&|]*)/g`.
  - From each match, take the whitespace-separated tokens up to the first one that starts with `-`, and keep those matching `/^[a-z0-9]+-[a-z0-9]+(?:\.\d+)*$/`.
  - Dedupe in order.
- **User prompts.**
  - Take user records that are not `isMeta` and not `isCompactSummary`.
  - String content is the text.
  - Array content is skipped entirely if any block is a `tool_result`. Otherwise join the `text` blocks whose `text.trimStart()` does not start with `<`.
  - Trim, and drop empty results.
- **Corrections.**
