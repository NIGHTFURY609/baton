# The `.context/` format

What `baton init` scaffolds and what every command reads. Six documents, not nine; each has one mutation rule. Parsing lives in `src/core/frontmatter.ts`; keep this file and that code in sync.

## Layout

```
AGENTS.md                 router, <= 60 lines, generated from .context/rules.md
CLAUDE.md                 one line: @AGENTS.md  (so Claude Code loads both)
.context/
  config.yaml             thresholds, packet budget, task backend, guards
  rules.md                source of AGENTS.md; sections of kind "rule"
  spec.md                 intent and boundaries; sections of kind "intent"
  STATE.md                generated by `baton handoff`; never hand-edited
  decisions/NNNN-*.md     MADR 4.0 records, written by baton decide; append-only (ADR 0018)
  knowledge/<topic>.md    how-to, patterns, gotchas; append then compact
  explain/<name>.md       voice templates for baton explain (ADR 0010)
  tasks.jsonl             task store (one task per line); changed only via `baton task`
  memories.jsonl          short project facts; changed only via `baton remember/forget`
  .cache/                 git-ignored: tasks.db, last-packet.txt/.json, drift.jsonl, stats/<session>.json, guard.jsonl, touched.jsonl
```

The task store is the sixth document (ADR 0009): `tasks.jsonl` is the committed truth, `.cache/tasks.db` an automatically rebuilt SQLite index. Both JSONL files use `merge=union` in `.gitattributes`. Beads can be used instead (`tasks.backend: beads`). There is no `todo.md` and no maintained mindmap: dependency views are derived from the task graph and code.

## Mutation rules

| Doc | Kind | Rule | Enforced by |
|---|---|---|---|
| rules.md → AGENTS.md | rule | Edit rules.md; AGENTS.md is regenerated | `compile --check` in CI (ADR 0022) |
| spec.md | intent | Rarely changes; a change to a load-bearing section needs an ADR | `decide`, `/init-spec` |
| decisions/ | decision | Created by baton decide; append-only: only a proposed record's body is edited by hand; status changes through decide --accept or a superseding record (ADR 0018) | PreToolUse deny (ADR 0020) |
| tasks.jsonl, memories.jsonl | — | Only through `baton task` / `baton remember` | PreToolUse deny (ADR 0020); tasks close through baton verify (ADR 0019) |
| STATE.md | state | Overwritten at PreCompact / SessionEnd, never appended | PreToolUse deny (ADR 0020) + `handoff` |
| knowledge/ | knowledge | Append, then periodic compaction | `/checkpoint`, `drift` (orphans, size) |

## Section provenance

Every section carries four fields (YAML, snake_case on disk):

| Field | Type | Meaning |
|---|---|---|
| `id` | kebab-case string, unique across `.context/` | Stable handle used by tasks (`spec:<id>` label), ADRs and `verify-doc` |
| `kind` | `rule \| intent \| decision \| state \| knowledge` | Picks the staleness threshold and mutation rule |
| `verified_at` | first 12 hex chars of a commit SHA, written quoted, or `null` (ADR 0012) | Last commit at which someone confirmed the section is true. `null` = unverified |
| `source_paths` | list of globs | Repo paths whose changes can make the section wrong. Empty = never ages by commits |

Optional: `superseded_by: <id or ADR number>`.

### Multi-section files (spec.md, rules.md)

An HTML comment directly under the heading, holding a YAML flow mapping. It is invisible when rendered and diffs as one line:

```markdown
## Authentication
<!-- baton: {id: auth, kind: intent, verified_at: 3f2a1c9, source_paths: ["src/auth/**"]} -->

Users sign in with passkeys. Sessions last 7 days.
```

A section runs until the next heading of the same or higher level. Unmarked headings are plain structure inside the enclosing section. Quote globs that start with `*` or contain `{`.

### Whole-file docs (STATE.md, knowledge/, decisions/)

Ordinary frontmatter:

```markdown
---
id: gotcha-windows-hooks
kind: knowledge
verified_at: 3f2a1c9
source_paths: ["plugin/hooks/**"]
---
# Windows hook gotchas
```

ADRs use MADR frontmatter plus baton's extension keys `id`, `kind: decision`, `supersedes`, `spec_sections`.

## Freshness levels

Computed by `classifyFreshness` (`src/core/freshness.ts`) from the commits in `verified_at..HEAD` that touch `source_paths`, plus dead references.

| Level | Condition (first match wins) | Packet policy |
|---|---|---|
| superseded | `superseded_by` set | Linked, not injected |
| unverified | `verified_at: null` | Withheld; listed as "needs verify" |
| stale | a dead reference, or commits ≥ `freshness.staleAfter[kind]` | Withheld; listed as "needs re-verify" |
| fresh | no `source_paths`, or 0 commits | Injected |
| aging | 1 ≤ commits < threshold | Injected with a one-line flag |

Changes to files under `.context/` are not counted (a commit that also touches other matching files still is), and dead references are defined in ADR 0013. A section that would be fresh, but has uncommitted changes (staged, unstaged or untracked, outside `.context/`) matching its `source_paths`, is aging (ADR 0021).

Default thresholds (`config.yaml`): rule 5, state 3, knowledge 10, intent 20, decision never (ADRs go stale only by supersession). Tuning them is a dogfood-phase question. Re-verification is cheap: `baton verify-doc <id>` stamps `verified_at` with HEAD.

## The mission packet

Assembled by `baton mission`, injected by the SessionStart hook. Blocks in priority order, each kept whole or dropped whole (`fitToBudget`):

0. State head: phase, blockers, last handoff warnings
1. Tasks: active first, then ready (max `packet.maxTasks`)
2. Freshness notices: aging flags and the "needs re-verify" list (ids only)
3. Spec sections tagged to those tasks (fresh or aging only)
4. ADR lines: accepted ADRs constraining those sections (one-line summaries)
5. Memories
6. Pointers: where to look for more (`.context/knowledge/`, `baton mission --task`)

The packet starts with the line `# baton mission brief`. When blocks are dropped, it ends with `Left out for space: <n> block(s) …` (ADR 0014).

Budget: `packet.maxChars`, default 9,000, hard maximum 10,000 (Claude Code's SessionStart cap; ADR 0004). Written as factual statements, not instructions.

## The task store

Ported from Beads (ADR 0009, THIRD_PARTY_NOTICES.md). One JSON object per line, sorted by id, empty fields omitted:

```json
{"_type":"issue","id":"bt-a3f.1","title":"Wire SessionStart hook","status":"open","priority":1,"issue_type":"task","created_at":"…","updated_at":"…","labels":["check:npm test","spec:hooks"],"dependencies":[{"issue_id":"bt-a3f.1","depends_on_id":"bt-a3f","type":"parent-child","created_at":"…"}]}
```

| Concept | Rule |
|---|---|
| Ids | `<prefix>-<base36 hash>`, 3–8 chars, growing with task count; children `<parent>.N`, max 3 levels |
| Status | `open`, `in_progress`, `blocked`, `deferred`, `closed` |
| Priority | 0 (most urgent) – 4, default 2 |
| Links | `blocks` and `parent-child` affect readiness and are cycle-checked; `related`, `discovered-from` are informational |
| Ready | open, no open `blocks` target, no blocked ancestor, not deferred (nor child of a deferred parent); sorted by priority, then age |
| Claim | open + unassigned (or already yours) → `in_progress`, assignee = actor; atomic across processes |
| Close | refused while children are open or a `blocks` target is open, unless `--force`; `baton verify <id>` closes only after its `check:` commands pass on a non-empty diff; `task close` on a task with a `check:` label needs `--force` and records "forced (check not run)" (ADR 0019) |
| baton labels | `spec:<section-id>` links a task to spec sections for the packet; `check:<command>` is what `baton verify` runs |

Actor: `--actor`, else `BATON_ACTOR`, else `git config user.name`, else the OS user.
